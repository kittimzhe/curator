## P2 问题(Why now)

**知识工作者"收得多、用得少、信不过"。**

- 用户现状:疯狂收藏文章/论文/笔记 → 永远不回头整理 → 知识库变垃圾场
- **瓶颈不在收集,而在入库前治理**:没有摘要、没有分类、没有关联,收藏≠知识
- RAG 时代新痛点:**垃圾进垃圾出**——把原文直丢向量库,检索质量随收藏量持续劣化
- 现有工具三个断层:
  - 笔记工具(Obsidian):存得住,不治理
  - 检索工具(khoj/各类 RAG):查得到,不保证进库质量
  - 收集工具(Pocket/Readwise):进得来,止步于"稍后读"

**一句话:市场缺少"知识入库前的治理系统"。**

---

## P3 解决方案(What)

**InsightLoom = 可见的多 Agent 治理流水线 + 人工审批 + 零锁定存储 + 本地语义检索。**

四项关键能力(全部已实现):

1. 👀 **看得见的治理**:分类员→摘要员∥链接员→质疑员→组装员,流水线全程可视
2. ✅ **人审批才落盘**:Agent 只产提案,一个字节不批不写;对抗式审查标记过度概括
3. 📄 **零锁定**:知识本体是磁盘上的 Markdown(Obsidian 直接打开),随时带走
4. 🔍 **本地语义检索**:本地向量库+本地嵌入,不出网即可检索与 RAG 问答(带引用)

## P5 技术壁垒(How)

- **架构壁垒**:LangGraph 状态机编排 5-Agent 流水线(分类路由/并行扇出/审查汇合/组装提案),每一步产出可追溯;三道闸门:幻觉过滤 → 对抗审查 → 人工审批
- **数据壁垒**:随使用增长,`[[双链]]` 网络与审批记录形成两类结构化资产——知识图谱越用越密,审批准则越用越准
- **工程壁垒**:自托管单机可跑;模型可替换(OpenAI 兼容/DeepSeek/Ollama 本地);嵌入推理完全本地(ONNX),检索不依赖云

## P6 市场与目标用户(Who)

目标用户(优先级):

1. **重度知识工作者**:研究者、咨询顾问、内容策略——日均收藏 10+ 篇,痛点最深

切入策略:**个人高频场景 → 开源社区获客 → 团队协作与私有化**。
对标参照:khoj(GitHub 37k+ 星)验证了"个人知识 AI"需求;InsightLoom 切的是它没做的治理层。

## 附:2 分钟 Demo 讲述稿

> (对应 demo.gif 节奏,可直接口播)

1. **(0:00-0:20)开场**:这是洞察织机。每个人都在疯狂收藏,但没人回头整理——我们让一队 AI 图书管理员替你干这活,而且全程看得见。
2. **(0:20-0:50)检索**:先看它已经记住的东西——输入"多Agent 系统如何管理状态",本地语义检索直接命中我的笔记小节;点"AI 回答",它基于我自己的知识库生成带引用的回答——不编造,答不了会说。
3. **(0:50-1:30)治理流水线**:投递一篇深度研究工作流的文章。看顶部舞台条:分类员判定深度、摘要员和链接员并行开工、质疑员对抗审查、组装员打包提案——每一个 Agent 的动作都实时可见。
4. **(1:30-1:55)审批闭环**:提案在审批台等馆长签字。点批准——笔记落盘成 Markdown,同时自动进入语义索引,下一秒就能被检索到。零锁定:这个文件夹拖进 Obsidian 直接能用。
5. **(1:55-2:00)收尾**:收集变知识,只在洞察织机。我们做的是知识入库前的治理系统。
