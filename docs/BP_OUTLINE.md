## 0. 使用说明（先看）

- 评委最关心三件事：**真实问题、真实产品、真实执行力**。
- 少讲概念，多讲“你已经做了什么、接下来 90 天做什么”。
- 每页控制在一个核心结论，避免大段文字。

## 1) 封面页

**标题建议**

- 洞察织机 InsightLoom
- 把收藏编织成可行动的洞察

**必须信息**

- 项目名称：洞察织机（InsightLoom）
- 团队名称 / 创始人
- 联系方式（邮箱 / 手机 / 微信）
- 官网：`insightloomapp.com`

---

## 2) 问题定义（Why now）

**要回答的问题**

- 用户现在怎么做？哪里痛？
- 为什么现有方案（笔记 / RAG / 第二大脑）不够？

**可直接用的句式**

- 知识工作者“收得多、用得少、信不过”，核心瓶颈不是收集，而是**入库前治理**。
- 现有工具偏“被动检索”，缺少“治理 + 审批 + 可追溯”的产品闭环。

---

## 3) 解决方案（What）

**核心一句话**

- InsightLoom = 收件箱 + 5-Agent 治理流水线 + 人工审批 + Markdown 知识沉淀。

**关键能力（3~4 点）**

- 看得见的治理流程（分类 / 摘要 / 互链 / 审查）
- 人工审批后落盘（可信可控）
- 纯 Markdown 零锁定（可迁移）
- 每日简报与巡库优化（持续增值）

---

## 4) 产品演示（Demo）

**建议结构（1 页）**

- 左侧放流程图：投递 → 治理 → 审批 → 入库
- 右侧放 UI 截图（当前工作台）
- 底部放 3 条真实操作结果（如“某内容 2 分钟完成治理入库”）

**一句话**

- 我们不是“再一个笔记工具”，而是“知识入库前的治理系统”。

---

## 5) 技术壁垒（How）

**建议写法**

- 架构壁垒：5-Agent 流水线 + 审批闸门 + 可追溯提案机制
- 数据壁垒：随着使用增长，双链网络和审批准则形成结构化资产
- 工程壁垒：自托管、可替换模型、离线友好

**可配图**

- 来自 `docs/PRODUCT_VISION.md` 的五层架构简图

---

## 6) 市场与目标用户（Who）

**目标用户（优先顺序）**

1. 重度知识工作者（研究、咨询、内容策略）
2. AI 原生小团队（需要共享知识沉淀）
3. 对数据可控有要求的团队（私有部署）

**市场切入策略**

- 从“个人高频场景”切入，再扩展到“团队协作与私有化部署”。

---

## 7) 竞争与差异化（Why us）

**对比维度建议**

- 是否可视化治理过程
- 是否支持“人审后落盘”
- 是否零锁定（Markdown）
- 是否强调知识质量治理而非仅检索

**结论句**

- InsightLoom 的差异不是“模型更大”，而是“治理链路更可信”。

---

## 8) 当前进展（Traction）

> 即使没有大规模用户，也要给出“执行证据”。

**可填模板**

- 产品状态：已完成 P0/P1a，具备端到端闭环

## 9) 商业模式与增长路径（Business）

**建议路径**

- Pro 个人版（月订阅）
- Team 团队版（协作与权限）
- Enterprise 私有化（部署服务 + 年费）

**增长策略**

- 内容分发（案例 / 模板）+ 社区口碑 + 产品内邀请机制

## 10) 未来 90 天计划（Execution Plan）

**按月拆解**

- M1：完成检索层 MVP + 5~10 位种子用户深访
- M2：上线问答与语义检索闭环 + 留存验证
- M3：打磨团队版最小功能 + 启动首个付费试点

**评委喜欢的表达**
