## 一句话证据主张

**InsightLoom 不是"调了 LLM 的笔记工具"，而是一条有对抗审查、有审批闸门、有幻觉防护的 Agent 治理流水线——并且它已经在真实内容上拦下过"过度概括"。**

---

## 证据 1：对抗审查确实拦下了"过度概括"（最硬的一条）

**真实案例**：`vault/RAG-检索质量的三个瓶颈.md`

- 摘要员把原文"结构化分块配合 **10-20% 重叠**"写成"配合重叠"，把 cross-encoder 重排"常见提升 **10% 以上** 端到端准确率"写成"可提升准确率"。
- **质疑员（skeptic agent）在落盘前拦截**，判定 `questioned`，并给出可执行修改意见：

> "补回'10-20% 重叠'和'10% 以上'两个限定。"

**这条为什么值钱**：它证明你的"对抗审查"不是营销词，而是**真实发生过、有留痕、可打开文件核对的拦截**。评委几乎在别的参赛项目里看不到这种证据。

**答辩话术**：`"我们的质疑员在一条 RAG 笔记入库前，抓到了摘要员丢掉的量化限定。这条记录现在就躺在我们的 vault 里，你可以当场打开核对。"`

## 证据 2：架构上的三道闸（代码级，随时可证）

| 闸门 | 实现位置 | 作用 |
|---|---|---|
| **fan-out / fan-in 并行** | `server/pipeline.py`（摘要员∥链接员→质疑员） | 摘要与互链并行，质疑员等两者都完成后对照原文审查 |
| **幻觉防护** | `server/pipeline.py` `link()`：`[c for c in connections if c in vault_notes]` | 链接员只允许引用**真实存在**的笔记，过滤 LLM 编造的双链 |
| **审批闸门** | `server/pipeline.py` `assemble()` → 只 `create_proposal`，不写 vault | Agent 只产"提案"，批准前一个字节不落盘 |

**答辩话术**：`"三道闸是写进代码的约束，不是提示词里的'请小心'。"`

## 证据 3：按需消耗 token（成本可解释）

**真实案例**：`vault/品牌升级回归测试.md`（`depth: read_later`）

- 短内容走"稍后读快车道"，**不触发**摘要/互链/对抗审查，直接进提案。
- 只有长内容（`deep`）才跑完整深加工。

**为什么值钱**：评委常问"Agent 流水线贵不贵"。这条证明你做了**按内容深度路由**，成本是可控的、按需的。
